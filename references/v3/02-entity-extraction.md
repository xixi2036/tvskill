# 阶段 02：角色、场景与道具提取

本阶段把归一化后的剧本变成一份**实体清单**，供资产生产与后续绑定使用。清单只是内部账本的一部分，不单独交付。

## 一、提取顺序

1. 通读全剧本，先列**出现过的全部实体**，不做取舍；
2. 再按下游需求判定每个实体**要不要做成生成资产**；
3. 最后为需要的实体确定**资产形态**(见 [资产生产合同](../libtv/asset-production-contract.md))。

先全列再筛，避免边读边筛漏掉只出现一次但镜头吃重的实体。

## 二、角色提取

### 2.1 判定"可识别人物"

一个角色需要独立人物图，当且仅当满足任一：

- 有台词、OS 或 VO；
- 面部在任一镜中可辨识；
- 跨段重复出现且观众需要认出是同一人；
- 承担关键动作或持有关键道具。

不满足以上的背景人物**不做独立人物图**，改由场景状态图统一管理人群占位。

### 2.2 每个角色登记

| 字段 | 内容 |
|---|---|
| 角色名 | 与剧本原文一致，作为下游 `@[角色-名]` 的语义标签 |
| canonical 外观 | 发型、面部特征、体型、默认服装；一处不确定就向用户确认，不自行发明 |
| 形态清单 | 换装、变身、受伤、年龄段等**互斥形态**逐个列出，每个形态单独一条 |
| 出场镜列表 | 用于判定需要几个视角 |
| 视角需求 | 由出场镜推导：是否有转身、越肩、背面、环绕、说话转头 |
| 音色需求 | 有台词则必须登记；音色未上传时登记为占位槽，下游节点保持阻塞直到关联真实音频 |

**形态是资产的单位，不是角色**。同一角色的两个形态是两份资产，各自独立锚定，不共用。

## 三、场景提取

### 3.1 逻辑场划分

按**空间连续性**而非按剧本场号划分：同一物理空间内连续发生的戏归为一个逻辑场，即使剧本分了多场；同一场号内跨越了不同空间则拆开。

### 3.2 每个逻辑场登记

| 字段 | 内容 |
|---|---|
| 场名 | 下游 `@[场景-名]` 的语义标签 |
| 空间拓扑 | 出入口位置、主要家具及其朝向、功能前方(如教室的黑板墙) |
| 世界坐标与轴线 | 供跨段保持一致 |
| 主光源 | 种类、世界方向、软硬、色温 |
| 人数状态 | 同一空间不同人数是**不同的场景状态**，各自登记 |
| 机位需求 | 下游会从哪些角度拍，决定资产是单图还是多视角 sheet |

同一空间的不同人数状态、不同时间光线状态，都是**独立资产**，不得用一张图承担互斥状态。

**★场名前缀是硬性要求，不是写法建议**：语义标签必须以 `场景-`、`场景状态-` 或 `人群状态-`
开头（如 `@[场景-Z班教室]`、`@[场景状态-Z班-占座]`）。校验器按名字前缀分类资产类型，
`场景-`/`场景状态-`/`人群状态-` 三个前缀之外的名字一律被当成人物资产处理——场景漏写前缀
不会报"这是场景吗"这类直接错误，而是被错误分类成角色后，在下游触发一连串看似无关的报错
（如"多人物缺身份数量锁"）。写完场名后自查：是否以这三个前缀之一开头。

## 四、道具提取

只登记**承担叙事功能**的道具：被持有、被交接、状态发生变化、或成为关键信息载体。

- 有互斥状态的道具按状态编号登记：`钢笔-A(扎墙)`、`报告-A-S0/S1/S2`；
- 纯陈设道具不单独登记，由场景图承担；
- 需要精确可见文字的道具，文字由**定版道具图**承担，不交给视频模型现场拼字。

## 五、色彩与媒介登记

- 每个逻辑场登记一条色板，跨场沿用或另立；同一逻辑场的全部资产共用同一张色卡图；
- 全剧登记一次**媒介**(真人实拍 / 2D 动漫 / 3D CG / 其它)，它决定所有资产图与视频段的写法，属于 `STYLE-ID` 的一部分，中途不得更换。

## 六、交接检查

进入资产生产前确认：

1. 所有有台词角色都有音色需求登记；
2. 所有互斥形态、互斥场景状态、互斥道具状态都已拆成独立条目；
3. 每个实体的视角需求已由出场镜推导，不是凭感觉给；
4. 媒介与色板已登记；
5. 存疑的 canonical 外观已向用户确认，没有自行发明的设定。
