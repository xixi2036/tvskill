# 资产生产合同

本文件覆盖从剧本到分镜之间缺失的一环：**把账本里登记的角色、场景、道具、色彩变成可以进 Mixed 的生成资产**。适用于用户没有现成素材、需要由本 skill 先造图的项目。

> 资料来源(仅供溯源)：对《万物生》《问心》两部上线作品的全部资产生成提示词做逆向。与 TVSkill 既有合同冲突时以既有合同为准。

## 0. 触发与边界

- **触发**：账本里某个人物、场景、道具或色彩在下游需要绑定，而用户没有提供对应素材。
- **不触发**：用户已提供可用素材时不重造；规划图(位置图、轨迹图、平面图、箭头图)不属于生成资产，永远不进 Mixed。
- **产物**：一份资产清单 + 每个资产一条图生成提示词。资产图生成完成并经人工确认后，才进入分镜阶段绑定。

## 1. 资产清单:从账本推导

按账本逐项判定"需不需要造、造成什么形态"：

| 账本条目 | 资产形态 | 判定依据 |
|---|---|---|
| 可识别人物 | 人物设定图 | **镜头看到几个面就锚几个面**：全程固定单侧 → 单图；有转身、环绕、越肩、跟拍背面 → 四视图(正面/侧面/正身/背面)；说话转头 → 至少含正面与侧脸 |
| 生物 / 载具 / 道具 / 场景 | 单图或多视图 sheet | 同上判据：下游会从几个角度拍，就锚几个面 |
| 同一人物的形态变化 | **每个形态各一张独立设定图** | 变身、换装、受伤、老少年龄段属于不同形态，两端各锚一张，不共用 |
| 逻辑场 | 场景状态图 | 单机位单区域 → 单图；多机位、跨区域、需要空间连续 → 多视角 sheet(远景全貌/俯瞰/关键机位内景) |
| 关键道具 | 道具状态图 | 有互斥状态(完整/破损、封口/展开)时**每个状态各一张**，与账本的道具编号一一对应 |
| 逻辑场色彩 | 色卡图 | 同一逻辑场共用一张；跨场换色板时另立 |
| 复杂调度段 | 故事板 | 仅当空间调度靠文字说不清时；**故事板属于规划图，不进 Mixed** |

同一世界内的所有资产必须共享一条 **DNA 声明**：统一的材质基调、统一的影棚或环境底、统一的光位与色温关系。DNA 不一致时，下游即使绑对了图，跨镜也会出现材质与色温跳变。

> **与 Seedance 官方 API 指南的两处分歧（均已裁定：按生产实证走）**
>
> **① 人物多视图 —— 用多视图。** 官方建议「大头照+全身照，不建议多视图」，理由是多视图易被识别成多个主体、加剧 ID 漂移与双胞胎。本合同**不采纳**：真实上线作品与本项目实拍经验都表明，按「看几面锚几面」给足视图，一致性更好。官方那条更像是对**素材质量不可控**场景的保守兜底。
>
> **② 素材数量 —— 按镜头需要给足，不卡 4-5 张。** 官方建议「4-5 个素材，不建议用满上限」。实测真实上线作品：**16% 的镜头绑 6-8 张**（1张16%／2张21%／3张15%／4张18%／5张10%／6-8张16%）。多角色同框、多生物、色卡+场景+人物并绑的镜头，压到 5 张会丢锁定项。
>
> 两条的共同逻辑：官方指南面向**通用 API 用户**的失败兜底，本合同面向**受控的短剧生产**。若实际出现 ID 漂移、双胞胎或特征优先级混乱，再按官方路线降级排查，不作为默认。

## 2. 图生成提示词的结构

资产图提示词是**结构化设计文档**，不是一句话描述。缺少结构会导致模型只渲染最后提到的特征。固定分节：

```
=== <资产名> v<版本> ===
【格式】画幅 + 分辨率 + 分格布局(几宫格/几视图) + 背景底(影棚灰/纯白/环境)
【设定】种属或身份 + 体型尺度(带单位) + signature 记忆点 + 参考混合来源
【DNA】本世界统一的材质、光位、色温、色板声明(与同世界其它资产一致)
【逐部位】按识别重要性排序，关键部位标 CRITICAL，逐项写死形状/材质/比例/颜色
【分格】每一格分别写清视角、姿态、可见范围
【光线】光位、软硬、色温、有无补光
【风格】2-3 个具体参考(影片/游戏/图鉴/摄影流派)，不用"精美""高质量"这类空词
【失败模式】本资产最可能跑歪的点，逐条写"易跑成 X → 必须是 Y"
```

## 3. 三条决定成败的写法

### 3.1 逐部位 CRITICAL

只写整体印象，模型会平均化每个部位。**把决定身份识别的部位逐个拆开写死**，并给最关键的 2-3 项标 CRITICAL。例如角色的疤痕位置、道具的开合结构、生物的头部形态。部位描述要给**形状 + 材质 + 相对比例**三项，只给形容词无效。

### 3.2 失败模式定向负向

通用缺陷词(模糊、畸变、多手指)不写。**写这个资产特有的、可预见的跑偏**，句式统一为"易跑成 X → 必须是 Y"：

- `易跑成普通鸟喙 → 必须是长直尖矛状、末端仅微钩`
- `易跑成胖体型 → 必须是精瘦长腿的疾走体态`
- `易跑成现代西装 → 必须是粗麻质地的对襟短打`

这类定向负向的价值在于**它同时给出了正确答案**，比单纯排除更有效。

### 3.3 量化锚

能量化的一律量化：体型给米数、分格给行列数、颜色给 HEX、镜头给焦段、比例给占画面几分之几。**多层多元素的资产同时给色卡与逐元素 HEX**；单主体简单资产只给色卡即可。

## 4. 媒介声明

资产图必须显式声明媒介，并与下游视频段一致：

- **真人实拍**：写实摄影质感、真实皮肤纹理与毛孔、自然光响应；用正向词声明实拍属性，不靠否定词堆砌。
- **2D 动漫**：明确线稿与上色方式、笔触、赛璐璐或厚涂、线条粗细。
- **3D CG**：明确渲染风格、材质 PBR 属性、次表面散射与否。
- **定格 / 其它**：显式写明工艺。

同一部作品内**媒介不得混用**；媒介同时决定资产图与视频段的写法，属于 `STYLE-ID` 的一部分。

## 5. 设计稿属性不得泄漏进成片

资产图带有大量**只服务于设计的元素**：分格线、视角标签、比例尺人形、影棚背景、色卡网格与 HEX 文字、四视图拼版。这些在资产图里是必要的，但**绝不能出现在成片里**。

处理方式是分两层：

1. **资产图层**：保留分格、标注、比例尺——它们就是设计稿的一部分；
2. **视频提示词层**：对绑定了这类资产的段落，写明**不继承**设计稿属性——不出现分格线、标注文字、比例尺、影棚背景、拼版布局。

参考图自带的**状态**同样要处理：湿身、破损、特定光线、特定背景，若本段不需要，必须在视频段显式覆盖，否则会被一并继承。

## 6. 迭代与验收

- **先低清试、再高清定**：构图与识别特征在低分辨率阶段就要能认出来；认不出说明提示词结构有问题，提高分辨率不会解决。
- **同一资产多版本**时保留版本号，账本记录当前 canonical 版本，下游只绑 canonical。
- **验收标准**：身份识别特征齐全、DNA 与同世界其它资产一致、无设计稿属性缺失或多余、互斥状态未混入同一张图。
- 资产未通过验收前，不得进入分镜绑定；不得用未验收资产当 canonical。

## 7. 角色根资产与互斥服装/状态的父子关系

一个角色若存在多套互斥服装或状态（如医院工作服、便装、变身态），必须建立**身份根资产 → 状态子资产**的继承关系，不得把多套互斥服装塞进同一张定妆图：

- 根资产先锁：五官、年龄、身高、体型、肤色、发型基线。
- 每个互斥服装/状态各建一个子资产（编号如 `<角色>-01`根、`<角色>-02`/`-03`子），子资产只允许改服装、发型整理方式和场景合理配件，其余字段从根资产继承。
- 子资产的起手 prompt 必须显式声明"互斥服装登记但不生成"清单，防止模型把未生成的分支一起画进当前图。

## 8. 起手默认为单图，四视图是派生步骤

起手（完整设计文档 + 文生图）默认输出 **单图**（全身定妆照），不做四宫格、不做拼贴。四视图是单图定版之后的**派生步骤**（对应第 2.4 步"转多视图"），不是起手格式本身。

例外：如果账本判定该资产下游镜头只需要单一固定角度（见第 1 节判据），可以不派生四视图，仅用单图 canonical。

## 9. 技术修复：锁光位 ≠ 禁止修光

技术修复 prompt 必须把"保持既定光效意图"和"修复技术性光影缺陷"拆成两个独立的要求，不能写成一句自相矛盾的话（反例：同一句里既说"不改变原图光影"又说"确保单侧侧逆光"）：

- **锁定项**：既定光位（主光方向、侧逆光方向）、色温、光比、整体明暗意图——不得因技术修复而改变。
- **修复项**：躁点、过度锐化、错误景深、脏斑、断层、跨格（四视图各格之间）光影不连续。

写法：先声明锁定项，再声明修复项，两者不得互相覆盖对方的措辞。

## 10. 标准四格布局的绝对规范

"2×2 四宫格、上面两格较小、下面两格较大" 不足以确定唯一版式，且**回看真实输出图**（而非只统计 prompt 文本）确认了以下几项之前被漏掉的结构，必须补全：

- **整图画布为 9:16 竖版**，不是正方形，也不是四格各自 16:9 拼接；四视图和单图起手共享同一竖版比例。
- **顶部整图标题栏**：浅灰底色横条 + 英文大写角色/资产名（如 `<角色名> — DEFAULT FORM CHARACTER SHEET`）。
- **每格下方英文字幕**：`FRONT FACE` / `SIDE FACE` / `BODY FRONT (NO FACE)` / `BACK`，同为浅灰底色横条。
- **格间有留白分隔**，不是无缝贴边拼接。
- **上下两行高度比例实测约 28:72**（上排明显更矮），不是均分。
- 四格内容默认为：左上正脸特写／右上侧脸特写／左下脖子以下全身（不含头）／右下背面全身；统一底为写实摄影棚定妆照 + 单侧侧逆光。

> 这套标题栏/字幕/分隔条样式在源 prompt 里大多未被显式要求，是模型对"character sheet"这一概念的默认联想；写新资产的四视图 prompt 时应**显式**写出标题栏文字、每格字幕文字和留白分隔，不能假设模型会自动带出，也不能只凭文本条款推断构图——**生成一批新资产类型的版式前，先回看至少 2-3 张同类型的真实输出图核对，再动笔写 prompt**。

### 10.1 "脖子以下不含头"格仅在高领/围巾类服装成立，开领服装改用带头分格

万物生真实素材里这一格能裁得干净，前提是角色穿高领、围巾或裹布——头部裁掉后颈部本来就被服装遮住。**若角色是圆领 T 恤、开领外套等裸露颈部的服装，同样的裁切规则会露出孤立、边缘生硬的颈部横切面**（实测反复出现，即使把裁切点描述改了三种不同写法——卡在下巴中间/镜头拉远露白背景/紧贴下巴——也没能稳定控制住，且三次失败方式互不相同）。这不是提示词精度可以解决的，是该格设计本身在开领服装上不成立。

**开领/圆领服装的替代分格**（参考 `huabu_studio` 的 `real-person-short-drama-v3` skill 的角色资产模板，该模板从设计上就不设无头格）：

| 格位 | 高领/围巾服装（默认） | 开领/圆领服装（替代） |
|---|---|---|
| 左上(小) | 正脸特写 | 正脸头肩特写（头颈完整可见） |
| 右上(小) | 侧脸特写 | 侧脸头肩特写（头颈完整可见） |
| 左下(大) | 脖子以下全身（不含头） | **全身正面（含头，不做无头裁切）** |
| 右下(大) | 背面全身 | 背面全身（含头） |

造资产前先看角色服装领口类型，决定用哪一套分格；不确定时默认使用"含头"版本，风险更低。

## 11. 四视图跨格一致性验收表

四视图定版前逐格核对，任一项跨格不一致即打回重做：

| 检查项 | 核对方式 |
|---|---|
| 面部身份 | 正脸与侧脸是否可判定为同一人（骨相、眼距、鼻梁、下颌） |
| 发际线与发长 | 四格是否一致，背面发长与正脸暗示的发量是否匹配 |
| 肩宽/头高比例 | 四格是否使用同一比例常量 |
| 服装款式与色彩 | 纽扣、口袋、衣长、裤脚、鞋型四格是否一致 |
| 配件数量 | 饰品/道具数量是否跨格一致，无凭空增减 |
| 光位与色温 | 四格是否统一主光方向、侧逆光方向与色温 |

## 12. Canonical 登记内容与版本回退链

Canonical 登记不能只存 prompt 文本，必须同时记录可复现所需的生成参数：

- 模型名称与版本、生成日期；
- seed（若模型暴露该参数）；
- 输出尺寸；
- 图生图强度/denoise（若适用）；
- 参考图列表及各自权重；
- 蒙版区域与羽化（若使用局部重绘）；
- 每轮结果的接受/拒绝原因。

迭代过程使用**不可覆盖的版本链**，每轮只从"上一个已通过质检"的版本继续，失败结果保留但不作为下一轮父图：

```
v0 起手 → v1 → v2 → … → CANON
```

## 13. Canonical 准入门槛（七项）

资产升级为 canonical、允许进入分镜绑定前，至少核对：

1. **身份**：正脸与侧脸是同一人，年龄段正确；
2. **比例**：头身比、身高感、肩胯与腿长跨格一致；
3. **服装**：款式、颜色、材质、口袋、袖长、衣长和鞋跨格一致；
4. **Signature**：本资产的关键记忆点（如念珠形态、职业制服结构）跨格保持一致；
5. **技术**：无躁点、无过锐、景深合理、光位统一；
6. **泄漏**：进入视频节点前已明确排除网格线、影棚背景、标签、reference-sheet 语义；
7. **复现**：已保存模型、seed、参数、父图与每轮变更记录（见第 12 节）。

> **★ 2026-07-27 追加实测：模型用错不只是质量下降，会导致任务挂起不返回。** 用 `Lib Image`（起手/文生图专用模型）执行 image2image 编辑任务时，连续两次卡在固定进度（53%／39%）15 分钟以上不返回，无报错、无失败状态，纯粹悬挂；换成 `General image V2`（对应 Nano 2，迭代/局部编辑专用）后同一编辑指令约 1 分钟内正常完成。**模型分工不是质量偏好，是可用性前提**——用错模型档位可能表现为任务卡死而非仅仅是效果打折，遇到生成任务长时间无响应，先检查是否用错了模型档位，而不是默认判定为平台不稳定。
>
> 以上第 7-13 节由 2026-07-27 P0 验证（新题材角色资产 dry run，见项目知识库 `17_P0_现代都市修仙角色资产生产全链.md`）中文本/逻辑层面确认的缺口固化而来。仍有部分判据（如某类改动应归为"局部微调"还是"重绘"的量化边界）尚未经真实生成验证，暂不写入本合同，留待真实生产数据积累后再补。
