# TVMao 视频节点交付合同（兼容 Markdown）

## 1. 交付方式

每集只交付一个 Markdown。每一生成段包含：

1. Mixed 上传/连接顺序；
2. 一个 `text` 代码块；
3. 代码块内完整的 TVSkill 成品提示词。

Markdown 中的 `@[语义资产] {{Mixed N}}` 为兼容内部 DSL，必须保留到确定性校验结束；
同步脚本写入 TVMao 时把它编译为 `@[图片:<nodeId>]/@[视频:<nodeId>]/@[音频:<nodeId>]`；
网页运行时再序列化为 `图片N/视频N/音频N`。人工直接操作 TVMao 时必须
使用编译后的 prompt，不能把 `{{Mixed N}}` 原样粘贴进 TVMao。

## 2. Markdown 固定结构

````markdown
# EP01｜LibTV 完成提示词

- 总时长：12秒
- 生成段：2个
- 模型：Seedance 2.0 Fast VIP
- 画幅：9:16
- 分辨率：480P

## 使用方法
## 公共素材清单
## 资产清单
## 全剧连续性声明
## 全剧连续性母版
## 生成段 V01｜段落简述
## 画面对账
## 段间衔接总表
## 语音对账
````

八个章节缺一即校验失败。`## 资产清单`（人物/场景/道具/色卡四类都要有行）与
`## 画面对账`（原剧本每条画面指令一行）是后补的两章，早期版本的骨架没有它们；
照本节搭骨架时不要漏。

不得加入 JSON、后台 URL、伪造节点 Key 或“另见 JSON”。

## 3. 生成段块

````markdown
## 生成段 V01｜入场

- 段号：3-1-A
- 时长：6秒
- 连续组：CG-ZCLASS-DAY01
- 前置段：开场
- 提示词二审：已通过
- 交付等级：正式
- 制作路线：独立角色音色＋原生声画同出
- 风险标签：同步对白
- 运行状态：可运行
- 连续性模式：场景母版
- 声音：开启
- 文字策略：无画面文字
- 音色状态：单知影已绑定独立音色参考

### Mixed 上传顺序

| Mixed | 素材 | 类型 | 绑定语义 |
|---|---|---|---|
| Mixed 1 | 单知影身份图 | 图片 | @[单知影] |
| Mixed 2 | 单知影音色参考-5s | 音频 | @[单知影音色] |
| Mixed 3 | 干净首帧 | 图片 | @[首帧-3-1-A] |
| Mixed 4 | Z班占座状态 | 图片 | @[场景状态-Z班-占座] |

### LibTV 完成提示词（整块复制）

```text
总体设定。将 @[单知影] {{Mixed 1}} 定义为 <主体1>；@[单知影音色] {{Mixed 2}} 只控制 <主体1> 的音色，不继承原台词、背景声、情绪和节奏；参考 @[首帧-3-1-A] {{Mixed 3}} 的干净构图和真实视线对象；将 @[场景状态-Z班-占座] {{Mixed 4}} 定义为 <场景1>。

单一连续镜头，无剪切。中近景，稳定三分之四侧机位。<主体1> 听见对方停下后才开口，视线落到对方右肩；她用 Mixed 2 的同一音色自然说出 {你，很吵。}，声音与口型同步；说完恢复鼻息并继续倾听。<环境底噪>。

真人实拍，右侧冷白窗光与室内顶灯方向固定。只锁当前脆弱的人物、嘴型、手或道具状态；保持无字幕，不生成可辨识文字、水印或 Logo。NOT slow motion+NOT 卡通渲染+NOT 换脸。
```

### 衔接

- 入点：开场。
- 出点：人物停稳。

### 状态交接

| 连续键 | 入点状态 | 出点状态 |
|---|---|---|
| character:单知影 | CH-DZY-v1-画面左 | CH-DZY-v1-画面左 |

### 剧本事实对账

| 类型 | 原剧本事实 | 提示词落实 | 结果 |
|---|---|---|---|
| 台词 | 单知影说“你，很吵。” | 代码块仅一次精确台词 | 通过 |
````

范例里的表格必须带真实数据行：状态交接与剧本事实对账都要求“至少一行有效行”，
只有表头会被校验器判为“没有有效状态行／没有有效事实行”。

## 4. Mixed 规则

- 每段独立从 `Mixed 1` 连续编号；
- 每个可识别人物使用独立人物图片和独立 Mixed；
- 人物图、首帧、场景状态图和道具图不得共用 Mixed；
- 教室、会议室、法庭等功能场景的群像状态图必须经过朝向验收；提示词写清功能前方、
  家具方向、人体下半身方向和允许的眼/头/肩转动；
- 规划位置图、轨迹图、构图图、箭头图和文字标注图不得上传到 Mixed；
- 上传表每一行对应一个实际图片、音频或视频；
- 代码块出现的每个 `{{Mixed N}}` 必须在上传表中存在；
- 上传表中的每个 `Mixed N` 必须在代码块中至少出现一次；
- 同一媒体在同段多次引用时复用编号；
- 不用同一编号绑定两个不同媒体；
- 无素材时保留可上传槽位和明确素材名，不编造媒体内容。

## 5. 时长和逐镜规则

- 每个视频生成节点默认设置为模型 `Seedance 2.0 Fast VIP`、画幅 `9:16`、分辨率 `480P`；
- 默认每段 4–15 秒，模型有明确限制时以实时 schema 为准；
- 段时长写在 Markdown 元数据和 TVMao `params.duration`，不写进模型代码块；
- 连续单镜只用于具有明确不中断表演价值的单一事件；10 秒以上还必须写`长镜头叙事意图：...`。多镜节点逐个 Shot 只允许一位说话人和一个自然意群；
- 确需片内剪切时使用行首精确 `Shot 1:`、`Shot 2:`，禁止旧 `镜头N：`；
- 多镜由时间/空间事件密度决定，按实际时长约 `÷3` 到 `÷2`：10–13 秒建议 3–5 个、14–15 秒默认 4–6 个清楚 `Shot N:`，每镜约 2–4 秒；
- 每个含台词、OS、VO 或旁白的 `Shot N:` 必须绑定该说话人的独立音色并开启声音；音色尚未由用户上传时留音色占位槽并把该段标为阻塞，关联真实音频后才可同步与运行；
- 每镜写一个主运镜、动作表情、空间变化和声音；
- 台词使用 `{}`，音效使用 `<>`，BGM 使用 `（）`；
- 模型代码块中的 `【】` 只允许 `【阶段N…】`、`【声音设计】`、`【关键约束】` 三类结构标记，其余一律不用；
- 段尾动作落定，便于下一段承接。

## 6. 人工操作顺序

先确定同步模式：

- 用户要求整集重新创建、全部使用新节点或明确说不用原视频节点时，运行
  `sync_delivery_markdown.py --fresh-set`。必须覆盖 Markdown 全部 V01–VNN，禁止 `--only`
  和 `--node`；旧视频节点全部冻结为历史，不得用“只改受影响段”的判断混入新集合。
- 用户只要求若干段另建版本时，使用 `--only` 且不传 `--node`。
- 只有用户明确要求修改既有、从未运行的节点时，才使用 `--node`；任何已运行节点都不得更新。

随后按以下顺序执行：

1. 用稳定 modelId `doubao-seedance-2-0-fast-260128` 新建 TVMao `video-generator`；整集重建时逐段回读新返回的唯一节点 ID；创建命令必须显式传非重叠 `--x/--y`，把本批节点按段号排在现有画布下方的可见网格中；
2. 按本段表格顺序连接 image/audio/video input；入边顺序就是模型输入顺序；
3. 设置 `ratio=9:16`、`resolution=480p` 和段头时长；TVMao schema 没有 `enableSound`，不得伪造该参数；
4. 用同步器把代码块的 Mixed DSL 编译为官方媒体引用后写入；
5. 用 `tvmao edge list --to <NODE_ID>` 回读并核对入边顺序；
6. 对 Seedance 输入逐一完成 `tvmao compliance verify/status`，全部 `active` 后才可运行；
7. 只运行“可运行”段；同一连续组后段等待前段验收；
8. 生成后完成身份、眼神、口型/声音、人数、道具、文字和衔接验收，硬失败不得续接。

整集重建完成后，对全部新节点做一次联合 `audit_canvas_nodes.py --pre-run`。只有段号集合与
Markdown 完全一致、全部节点 `idle/runCount=0` 且审计 `errors=0 warnings=0`，才能报告
“整套新视频节点已就绪”。还要回读新节点坐标并确认全部互不相同；全部落在 `(0,0)`、
任意重叠、部分创建、部分审计或新旧节点混合均视为未完成。

## 7. 交付前二审

先完成全部提示词初稿，再按全剧连续性时间线做一次独立二审。逐段核对原剧本事实、
Mixed 职责、段内矛盾、前后段状态、跨集版本和模型任务复杂度；发现问题后回写提示词，
不能只在备注中披露。运行单集校验和全剧连续性校验均为零错误后才交付。
