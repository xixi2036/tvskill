# 起手帧合成合同

> **它取代了什么**：此前 tvskill 把「角色板＋空场景锚＋色卡」直接绑给视频节点，
> 让视频模型现场组构图。本合同改为：**先用图像模型把这一镜钉成一张确定的画面，
> 视频模型只负责让它动。**
>
> **依据**（用户 2026-09-04 裁决以此两者为准）：
> - 万物生真实产线：362 节点、**319 条 image→video 连线**是骨架
> - 豆包官方 `doubao-creative-drama`：`frame` 是 `assets` 与 `prompt` 之间的**独立阶段**

---

## 1. 为什么必须有这一步

万物生作者原话：

> 「Seedance 图生视频对『第一帧长什么样』极其敏感。作者**不直接文生视频**，
> 而是先用图像模型把这一镜的**构图、角色站位、光影色调定死成一张图**，
> 再让 Seedance 从这张图动起来。这是保证画面可控的根本手法。」

**实证代价**（《万妖图录传》EP01 回归，2026-09-04）：
没有起手帧时，构图只能靠文字描述「虎妖占画面右侧四成、低机位仰拍」——
模型不听，成片里虎妖偏小偏远，与参考成片的纪念碑式压迫感差一档。
提示词也因此被迫用大量文字去描述构图，而那本该由一张图承担。

---

## 2. 起手帧不是场景图

这是最容易搞错的一点，tvskill 此前正是错在这里。

| | 空场景锚（**旧做法，已废弃**） | 起手帧（**新做法**） |
|---|---|---|
| 人物 | 明写「画面中**不出现任何人物**」 | **人物在位**，姿态、朝向、站位确定 |
| 构图 | 「留出中景右侧可放置大型卧倒主体的空地」 | 每个元素在画幅中的**位置与占比写死** |
| 机位 | 只写「可行机位」 | **焦段 mm ＋ 离地高度 cm ＋ 俯仰角度 °** 写死 |
| 用途 | 供视频模型参考空间 | **本镜第一帧本身** |

**量化佐证**：万物生 127 条图片提示词中，**0 条**写「不出现任何人物」；40% 含人物描述。

场景参考图**不废弃**，降级为「合成起手帧时的空间底子」，不再直接进视频节点。

---

## 3. 起手帧提示词骨架（取自万物生真值）

真值样本：`万物生第1集 段3关键帧B 24mm低机位贴地仰拍刘回骑赛加狂奔起手帧`
（绑定 5 张参考图：角色＋座骑＋远景飞船＋远景沙艇＋色卡）

```text
【用途】<本镜时长> 秒视频的起手帧锚定 ＋ 起手姿态 ＋ <焦段/机位手法> ＋ <构图对标>

[STYLE LOCK 风格锚定]
<胶片/渲染语言> ＋ <摄影师或导演对标> ＋ <影片段落对标> ＋ <画幅>

[REFERENCE LOCK 参考锁定]
@[<角色资产>] 作为<角色名>的视觉锚定 ＋ <2–4 个稳定识别特征> 严格按此图渲染。
@[<道具资产>] 作为<道具名>的视觉锚定 ＋ <形态/材质/状态> 严格按此图渲染。
@[<色卡>] 作为整张图色卡锚定 ＋ 所有色彩严格按色卡 13 色执行 ＋ 不可偏离色板。

[镜头与机位]
Camera: <焦段>mm ＋ <镜头性格：广角桶形畸变/长焦压缩/标准>
Camera position: 离地约 <N>cm ＋ 相对主体的方位 ＋ 俯仰 <N>°
Frame: <画幅> 单帧

[构图]
<主体A> 位于画面<方位>，占画幅<比例>；<主体B> 位于……；
前景／中景／远景各是什么；光从哪来、落在哪。
```

**四个块缺一不可**：只有 STYLE LOCK 会漂风格，只有 REFERENCE LOCK 会漂构图，
没有[镜头与机位]会得到随机景别，没有[构图]会得到随机站位。

**STYLE LOCK 的四个尖括号怎么填**：`<胶片/渲染语言>` 与
`<摄影师或导演对标>`／`<影片段落对标>` 的可选词库见
[成像基底与光学缺陷库](optical-substrate-library.md)——先按 `LOOK-ID` 的保真取向判断
是否适用（低保真取向与风格化 3D 不适用），再选**一个**成像基底和**一个**主导光学缺陷家族。
`<画幅>` **不写进提示词**：tvskill 交付竖屏，画幅由 TVMao 节点参数负责，
外部素材里的 `2.39:1 / 21:9` 一律不迁移。

构图块写完后，按
[调度构图光线](../v3/04b-blocking-composition-lighting.md) §4.1b 做一次视线流量自检，
过关再发送。

## 4. 每段锁几张

采用豆包官方的判据，**默认 1 张**：

- **默认**：每段 1 张起手帧。
- **递增条件**：段内信息量高、状态切换密集、命中多条独立判定标准且分别落在不同时间段时，
  才增到 2–3 张（此时后续张声明为「中段锚点」或「尾帧」，附对应绝对时间点）。
- **禁止套模板**：**不得**默认按「首帧＋中段＋尾帧」三分法拉满 3 张；
  位置在首/尾本身不构成入选理由。

**判定标准**（命中一条即为候选）：决定性瞬间／情节转折／身份亮相／状态突变／
角色造型改变／空间锚点建立／视角体系切换／群像结构定格／光影转折。

**逆向排除**：纯转场镜头、黑场、极高动态模糊镜头、无可视主体的过渡帧。

## 5. 视频节点怎么绑

```
video-generator 的入边：
  ① 起手帧（image-input）        ← 必须，且排在最前
  ② 角色资产（image-input）      ← 锁身份漂移，1–2 张
  ③ 音色（audio-input）          ← 有台词时
  ④ 上段尾帧（image-input）      ← 非首段时，标注为「承接参考帧」
  ⑤ 色卡（image-input）          ← 默认绑，可豁免（万物生 47%）
```

**场景锚与规划板不再进视频节点**——空间信息已由起手帧承载。
豆包官方原文：「关键帧本身已经承载了场景空间、构图、光影、道具位置等信息，
因此视频 Prompt 默认不建议再额外传入场景资产图，避免参考冲突。」

万物生实测每条视频提示词引用 **均 4.3 个、中位 4 个**素材，与上表吻合。

## 6. 视频提示词里怎么写起手帧

```text
@[起手帧-VNN] 为本段起手帧，0 秒画面必须与其一致。
```

**画面细节仍要写**（用户 2026-09-04 裁决，走万物生路线）：
万物生有起手帧的提示词与没有的一样写满画面分区描述
（2223 字 vs 2300 字、画面分区 72% vs 71%），并不因为有图就省略文字。

与豆包官方「文字不复述画面元素」的分歧已知，本项目取万物生口径：
**起手帧钉构图，文字仍写画面**，双保险。

## 7. 复查方法

```bash
# 起手帧是否真的含人物（不该出现「不出现任何人物」）
grep -c "不出现任何人物" <起手帧提示词>     # 应为 0

# 视频节点入边是否以起手帧打头、且不含场景锚
tvmao edge list --to <视频节点> --project <N>
```

## 8. 生图模型：请求 id 用 `gpt-image-2.1`

画布模型列表里两行看着像两个模型，实际是**同一个模型的 id 与显示名**：

| 请求用的 modelId | 列表显示名 |
|---|---|
| `gpt-image-2.1` | gpt-image-2（稳定） |
| `gpt-image-2` | gpt-image-2 ← **这行不能用作请求 id** |

拿 `gpt-image-2` 作 modelId 提交，CLI 会收下并返回 taskId，
但上游立刻回 `404 Model "gpt-image-2" is not supported`。

**口径**：一切生图节点的 `--model` 一律写 `gpt-image-2.1`。

> 2026-09-04 记录一次误判：起手帧批量超时时，我一度怀疑是模型选错并把
> 「应改用 gpt-image-2」写进了本合同，实测 404 后撤回。模型从头到尾没错过；
> 真实原因是**一次性并发提交 12 张**（见下节）。

---

## 9. 生成必须串行（2026-09-04 实证）

**一次性并发提交会整批超时。** 实测：12 张起手帧同时 `node run` 提交后，
**10 张返回 `context deadline exceeded`**，只有最后 2 张排到队列尾部得以完成。

这类失败**没有产出任何画面**，属基础设施超时而非生成被拒——与内容策略拒绝
（`content_policy_violation`）和审核拒绝（`InputImageSensitiveContentDetected`）
是不同性质，**失败节点可以原地重跑**，不受一次性视频预算约束
（那条约束针对的是「不改任何变量的盲目重摇」）。

**做法**：资产与起手帧一律**一张跑完再跑下一张**。
视频侧的 `run_episode_sequence.py` 本就是串行的；图像侧此前没有对应工具，
批量脚本必须自己串行，不要图快并发。
