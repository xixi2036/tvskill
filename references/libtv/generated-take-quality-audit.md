# 生成成片回收、质量审计与返工合同

本合同把生成完成后的下载、取证、验收和返工固化为 TVSkill 自己的知识。它综合本
skill 内的制作准入规则、Seedance 参考竞争机制、连续性检查和定向返工方法；运行时
不依赖其它 skill。生成成功只表示平台返回媒体，不表示镜头合格。

## 1. 三层事实

审计时必须分开记录，禁止用计划替代事实：

1. **画布事实**：实时 prompt、稳定 modelId、扁平 params、有序输入边、素材合规状态和任务状态；
2. **媒体事实**：文件名、时长、分辨率、帧率、是否有音轨、音轨编码；
3. **观察事实**：逐镜观看和复听得到的人物、眼神、动作、台词、空间、道具、文字和声音。

优先级为“观察到的已验收成片状态 > 画布实时事实 > Markdown 计划”。自动语音识别只
用于发现疑点，专名、数字、短句和情绪必须人工复听，不能把 ASR 猜测当作逐字真值。

## 2. 回收范围

每轮审计必须先列出目标前缀下所有 video 节点，再区分：

- 已生成且有可下载 URL；
- 已运行但失败或没有 URL；
- 未运行；
- 历史版本、预览版本和候选版本。

下载所有“已生成且有 URL”的版本，而不是只下载最新节点。保留原节点名，避免不同版本
互相覆盖。每个文件至少取得：

- 媒体技术信息；
- 每秒一帧或足以覆盖全片的接触表；
- 有音轨片段的试听结果；需要时生成离线 ASR 疑点表；
- 首帧、动作峰值帧、对白中段帧和稳定末帧。

下载完成后可用自带脚本生成技术事实表和接触表：

```bash
python3 scripts/audit_take_files.py <下载目录> \
  --out <技术审计.md> \
  --contact-sheets
```

脚本只负责媒体事实和接触表，不自动声称人物、表演或连续性合格。

## 3. 十轴逐片审计

每条视频按同一顺序检查：

1. **节点与参考**：Mixed 语义和实际顺序一致；无规划图；说话人音色齐全；
2. **人物身份**：脸、年龄、发型、服装、身形和人物数量稳定；
3. **表演与眼神**：开口触发可见；目光落在具体目标；无无故直视镜头；表情不过度；
4. **对白与声音**：台词逐字、说话人、口型、音色、节奏正确；无串音、抢话和意外人声；
5. **空间与人群**：轴线、左右、距离、座位、门窗和占座状态与前后段一致；功能场景的
   前方、家具和人体默认朝向成立；
6. **动作、道具与物理**：动作完成且落稳；手别、持有者、数量、接触、轨迹和状态正确；
7. **镜头与剪辑**：景别服务叙事；镜头数量兑现；无无意义慢推、重复动作和机器人正面口播；
8. **光影、质感与风格**：主光方向、色温、对比、肤色、材质、颗粒和镜头语言符合 `LOOK-ID`；
9. **文字与画面卫生**：无烧录字幕、乱码、箭头、虚线、图例、UI、水印或 Logo；
10. **边界连续性**：首尾状态明确，相邻段并排可剪；末帧没有闭眼、口型中途或动作悬空。

## 4. 立即拒绝项

以下任一项成立，片段不得进入正片或续接链：

- Mixed 错位、规划图或错误场景实际进入模型；
- 缺少应有音轨、说话人音色未绑定、错词、漏词、串音或意外人声；
- 主角身份漂移、人物复制、人数或占座状态突变；
- 黑板/讲台与课桌、座椅、学生坐姿形成不可能的教学朝向，或群像整排反坐；
- 箭头、虚线、图示、烧录字幕、乱码、精确文字错误；
- 眼神目标错误、直视镜头、明显口型迟滞；
- 道具穿模、悬浮、复制、持有者或状态错误；
- 动作未完成、首尾不可剪，或后段不可能继承前段真实出点。

已有结果的节点若生成前审计存在硬错误，其成片默认为拒绝态；只有逐片证明对应错误没有
污染画面且其余十轴通过，才可重新考虑。不能因“总体还能看”跳过结构性违规。

## 5. 判定与返工

### 5.0 视频一次性预算

- 同一视频节点与同一提示词指纹最多运行一次；提交后立即把该节点记为已消耗，禁止重试或重新生成。
- 首次运行前必须把人物、场景、道具、首帧、音色、入边顺序、台词和空间连续性审完，图片问题优先在 Codex 图像链中多轮修正，不用视频算力试错。
- 唯一一次结果硬失败时，原节点永久保留为拒绝证据。只有根因和主要失败变量已经改变，且形成新的提示词指纹、引用集合和版本化节点时，才允许新的单次运行。
- 只追加否定词、只换随机性或在原节点点击重试，不算返工方案，也不得消耗新的视频预算。

每条片只使用以下五种结论：

- **保留**：十轴通过，可进入连续性链；
- **后期修复**：画面主体合格，问题明确属于声音、文字、调色、裁切或少量尾帧；
- **局部编辑**：只有一个画面层错误，平台确有可控编辑能力；
- **重抽**：节点设计正确，单次采样异常；
- **重写/拆段**：参考冲突、任务过载，或同一硬伤已经出现两次。

一次返工只改变一个主要变量，并写成“故障 → 根因层 → 单变量动作 → 验收证据”。图片类变量可在 Codex 图像链中反复迭代；视频节点不得复跑：

- 参考污染 → 移除污染资产并用干净帧重锚；
- 身份漂移 → 减少竞争参考或改用干净身份/脸部锚；
- 表演机械 → 减少声音和动作控制，只保留目标、触发、一个真实动作；
- 对白拥挤 → 单一说话人、单一自然意群、稳定机位，OS/VO 独立 Shot；
- 道具失败 → 独立道具任务、清楚起终态，精确文字移交后期；
- 连续性失败 → 使用前段已验收出点或重做干净首帧，不能续接拒绝片。

同一硬伤第二次出现时，必须重写、拆段、换资产或改制作路线，不得继续追加否定词。

## 6. 注意力和事件预算

人物身份、复杂动作、场景密度、原生对白、镜头切换和精确道具会竞争同一生成预算。
每个 Shot 只选一个主要保真目标，其余保持稳定：

- 对白近景：主要预算给身份、眼神、口型和声音；背景只做低幅持续微动；
- 高速动作：主要预算给轨迹和接触；不同时承担长台词或群体反应；
- 群体全景：主要预算给人数、占座和传播节拍；不要求多名可辨识人物同时细演；
- 道具特写：主要预算给手、道具和接触；人物表演与运镜降到最低。

原生多镜的 `Shot N:` 是具备独立叙事功能的段内子镜头。按实际时长约 `÷3` 到 `÷2`
配置：10–13 秒建议 3–5 镜，14–15 秒默认 4–6 镜，每镜通常 2–4 秒。审计时检查建立、
说话、反应、插入、关系和落幅是否按剧情需要分配；不得把完整 15 秒压成单镜默认模板，
也不得用平均不足 1.5 秒的无功能快切机械凑数。

## 7. 全剧装配复核

单片通过后，仍须按剧本顺序装配并复核：

- 相邻首尾帧并排比较人物比例、视线方向、主光、座位和道具；
- 每个场景连续组比较人群密度、背景位置、曝光和色彩；
- 每个角色跨片试听音色、语速、气口和响度；
- 检查动作因果是否完整，不能只靠单片“好看”；
- 每两到三段用 canonical 人物、场景和道具重新锚定，避免尾帧误差级联；
- 只有全部硬失败退出装配链后，才报告该场景或该集“可交付”。

## 8. 审计报告最小格式

报告必须是 Markdown，至少包含：

- 项目、节点前缀、下载时间、已生成/未生成数量；
- 每条视频的媒体事实、观察问题、判定和单变量返工动作；
- 全剧/全场景连续性问题；
- 画布事实审计总数与错误数；
- 哪些片段被允许作为续接来源；
- 本轮对 skill、资产或提示词合同做了哪些改动。
