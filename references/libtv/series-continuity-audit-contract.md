# 全剧提示词二审合同

本合同规定提示词初稿完成后的强制第二遍检查。二审不是润色，而是把全剧剧本、既有
提示词、已验收成片状态和当前生成段放在同一个连续性时间线上复核。未通过二审的
Markdown 不能交付，未通过成片验收的状态不能写成连续性真值。

## 1. 审核范围

- 用户提供全剧剧本或全剧提示词时，先完成全部初稿，再做一次全剧横向二审；
- 只提供单集时，必须读取同项目已存在的前集提示词和连续性声明，审核范围写
  `截至EPXX`；不得伪称已经检查未提供的未来集；
- 完全没有其它集资料时写 `单集`，同时把“缺少前后集资料”列为范围限制；
- 新增或修改任一集后，重新审核受影响连续组，不只检查改动文件。

## 2. 三层真值

优先级从高到低：

1. 原剧本事实：台词、人物关系、场次、明确动作、时间推进；
2. 已验收成片观察状态：实际人物位置、道具、人数、光向和稳定末帧；
3. 提示词计划状态：尚未生成部分的预期入点与出点。

计划状态不得覆盖剧本事实；未验收视频不得覆盖计划状态；拒绝片段不得进入任何后段
的前置依赖。

## 3. 每集必须保存的连续性信息

在同一个交付 Markdown 中加入：

### 全剧连续性声明

- 剧名；
- 审核范围：`全剧`、`截至EPXX` 或 `单集`；
- 剧情时间锚；
- 前集承接；
- 本集最终出点；
- 全剧二审：只有完成二审后才能写 `已通过`。

### 全剧连续性母版

每个跨段稳定元素使用机器可比较的连续键：

- `character:角色名`：脸型、年龄段、发型和体态版本；
- `wardrobe:角色名`：当前服装版本；
- `scene:地点名`：空间结构、门窗、座位、主光方向；
- `topology:地点名`：功能前方、家具朝向、人体默认使用方向和允许转动层级；
- `population:地点名`：当前人数和占位版本；
- `prop:道具实例`：实例、持有者、手别、位置和状态；
- `timeline:主线`：剧情日、时段和天气；
- `axis:连续组`：屏幕方向、对切轴线和出入口。

同一连续键跨集必须复用同一锁定版本。确需变化时，把“本集允许变化”写为 `是`，
并给出能回指原剧本的变更依据；仅写“剧情需要”不能通过。

### 每段状态交接

每个生成段增加：

- `连续组`：同一场连续镜头使用同一标识；
- `前置段`：`开场`、`独立` 或已经存在的 `EPXX-VNN`；
- `提示词二审`：修订完成后写 `已通过`；
- 状态交接表：列出本段实际涉及的连续键、入点状态和出点状态。

状态值使用短而稳定的生产代码或明确短语；同一状态不要换同义词。连续组内，同一键
的前段出点必须等于后段入点。剧本明确发生变化时，变化必须发生在某一段的可见动作中，
不能在两个生成段之间无解释跳变。

### 每段剧本事实对账

逐段建立“类型 / 原剧本事实 / 提示词落实 / 结果”表，至少覆盖本段实际存在的：

- 精确台词、OS/VO 和音效；
- 主动作及其先后顺序；
- 眼神对象、人物关系和情绪事实；
- 场景、时间、人群与关键道具；
- 画面文字或后期文字责任。

“提示词落实”必须指出代码块中的具体动作、台词或制作路线，不能只写“已处理”。
原剧本没有的事实不得为了让镜头更丰富而补入。对账有一项不是 `通过` 时，提示词二审
必须保持 `未通过`。

## 4. 七遍审核顺序

1. **原文准确性**：逐句核对台词、OS/VO、动作顺序、人物关系；禁止补写剧情事实；
2. **原子任务**：检查每段是否只有一个主要生成难题，对白段是否一镜一人一意群；
3. **资产职责**：逐项核对 Mixed 与提示词引用；规划图、冲突场景、错误道具状态和
   未验收末帧不得进入；
4. **段内一致性**：检查声音开关、文字策略、人数、眼神对象、物理光、道具实例、
   起止状态是否互相矛盾；
5. **段间连续性**：按连续组核对前置段、人物位置、轴线、功能朝向、光向、人数、道具和动作边界；
6. **跨集连续性**：按连续键核对人物/服装/场景/功能拓扑/人群/道具/时间线版本和前集出点；
7. **模型可执行性**：删除竞争任务、重复控制和模糊代词，确认时长足够且没有靠否定词
   修复结构问题。

先列问题，再修订提示词和状态表，最后从第一遍重新检查。不能边检查边默认原稿正确。

## 5. 二审硬失败

出现任一项即不得写“已通过”：

- 原台词遗漏、重复、换序或改写；
- 人物身份、服装或场景版本无依据变化；
- 连续组内前段出点与后段入点不一致；
- 前置段不存在、顺序倒置或来自拒绝片段；
- 道具实例复制、持有者/手别/位置无可见动作跳变；
- 空场景与可见人群、声音关闭与原生可听对白、零文字与模型精确写字等自相矛盾；
- 同步对白缺少真实眼神对象，或与走位、递物、特效、OS/VO、群体反应竞争；
- 把待验收计划状态写成已观察真值；
- 审核范围不是全剧，却写“全剧已检查”。

## 6. 交付与复查

确定性检查使用：

```bash
python3 scripts/validate_delivery_md.py <本集.md>
python3 scripts/audit_series_continuity.py <剧集提示词目录或多个Markdown>
```

脚本通过后，再由 LLM 按七遍顺序做语义二审。脚本负责格式、依赖、版本和状态相等；
LLM 负责判断变化是否真的有剧本依据、眼神是否有戏剧目标、动作是否可拍以及拆分是否
提高成功率。两者都通过才可以在 Markdown 写 `全剧二审：已通过` 和
`提示词二审：已通过`。
