# Seedance 2.0 × LibTV 适配

本文件把 Seedance 2.0 的模型能力收敛为 TVSkill 的当前执行规则。唯一交付源是每集
LibTV Markdown；旧 `script.rows`、payload、manifest 和 JSON bundle 不属于当前流程。

## 1. 任务结构

- 整集先做完整导演规划，再切为 4–15 秒生成段；
- 每段只承担一个主要保真目标：同步对白、复杂动作、群体状态或关键道具；
- 时间与空间变化都少且不中断表演本身具有叙事价值时，才用单一连续镜头；10 秒以上必须写明`长镜头叙事意图：...`；
- 存在多事件链、状态递进、对话往返、换机位或跨区域运动时，用 `Shot 1:` / `Shot 2:`
  多镜结构或在自然完成点拆节点；
- 多镜按实际时长约 `÷3` 到 `÷2` 配置：10–13 秒建议 3–5 个 Shot，14–15 秒默认 4–6 个 Shot，每镜约 2–4 秒并承担明确分镜功能；
- 段时长写在 Markdown 和节点参数中，不在最终代码块写绝对时间码。

默认节点参数为 `Seedance 2.0 Fast VIP`、`9:16`、`480P`、声音开启。用户明确覆盖或实时
schema 不同才调整。

## 2. 空间层与时间层

Mixed 素材负责给出稳定空间事实：

- 独立人物图锁身份、五官、发型与服装；
- 干净首帧或已验收续接帧锁起始构图、位置、视线对象和道具状态；
- 当前人数场景状态图锁空间、物理光源、人群占位和功能朝向；
- 当前状态道具图锁实例、持有者与可见状态；
- 独立角色音频只锁指定人物音色。

文字提示负责本段时间增量：

- 开口或动作触发；
- 一个主要动作和最多一个有动机的身体变化；
- 具体眼神对象；
- 一种主运镜或固定机位；
- 完整落幅及下一段需要继承的状态；
- 环境声、精确台词与说完后的活状态。

不要把多个互相冲突的首帧、人数状态或道具状态同时绑定。规划图不进入 Mixed。

## 3. LibTV 引用语法

最终代码块只使用 `@[语义资产] {{Mixed N}}` 这一兼容内部 DSL：

- 每段从 Mixed 1 连续编号；
- 上传表与代码块同序；同步时确定性编译为画布 `@[图片:<nodeId>]（label）` 等 node-id mention，
  网页运行时按实时有序入边序列化为 `图片N（label）`/`视频N（label）`/`音频N（label）`
  （三类媒体各自编号），用 `edge list --to` 回读校验，不存在额外 `mixedListOrder` 字段；
- Markdown 层不裸写 `@图片N`、`@视频N`、`@音频N`；
- 不裸写资产 ID、URL 或节点 Key；
- 每个素材只承担一个职责，不同人物和不同媒体职责不得共享 Mixed；
- 人物图不继承原背景、姿势或直视镜头视线；
- 场景图不继承错误人数或错误家具朝向；
- 音色音频不继承原台词、背景声、情绪和节奏；
- 动作参考只继承运动节奏和轨迹，不继承人物、服装和场景。

人物超过四名或群像身份难以稳定时，优先按叙事焦点拆镜，并用经过验收的当前人数场景
状态图管理背景人群，不用九宫格或多人拼图代替独立人物图。

## 4. 人物、表演与多人镜头

- 同一角色跨段复用 canonical 身份和服装版本；
- 情绪必须转成眼神、下颌、眉眼、肩颈、呼吸、手指或重心等可见表演；
- 同步对白写清开口触发、具体视线目标、精确台词、零或一个身体变化、零或一个声音控制、
  说完后的活状态；
- 多人镜头只有一个焦点人物，最多一人作一次小反应，其余人物维持非同步微动；
- 固定人物数量、屏幕左右、前后层级、视线轴和道具持有关系；
- 教室、会议室、法庭等功能场景必须锁定功能前方、家具方向和人体下半身使用方向；
- 学生回看只允许眼、头和少量肩部变化，骨盆、膝盖、双脚、座椅和课桌仍朝黑板。

## 5. 台词、声音与文字

- 剧本原文是唯一台词真值，不删句、不改写、不合并、不重复；
- 台词放在 `{}`，音效放在 `<>`，BGM 放在 `（）`；
- 每个含台词、OS、VO 或旁白的 Shot 只允许一名说话人和一个自然意群；
- 每名实际说话人绑定自己的已审核独立音色，声音开启；
- 缺任一说话人音色时节点阻塞，不能静音绕过或借用他人音色；
- 精确可见文字使用定版道具图或后期叠加，不交给视频模型现场拼字；
- 零文字任务保持无字幕、无可辨识文字、无水印和无 Logo。

## 6. 连续性与验收

每段内部记录计划起点、计划终点、实际起点、实际终点、完成节拍和保留节拍。同一连续组：

1. 复用 canonical 人物、服装、场景、道具、音色、轴线和 `LOOK-ID`；
2. 按顺序生成，不并行抢跑后段；
3. 前段下载并通过十轴验收后，才导出稳定续接帧；
4. 续接帧只允许一跳，并与 canonical 资产共同绑定；
5. 拒绝片段和未验收尾帧不得成为下游真值；
6. 每两到三段或新建立镜重新锚定 canonical。

成片至少核对身份、表演与眼神、逐字台词与音色、空间和群像、道具物理、镜头剪辑、
光影质感、画面卫生及相邻可剪辑性。硬失败返工必须改变失败变量，不能只追加否定词重跑。

## 7. 生成就绪门禁

只有同时满足以下条件才能标为“可运行”：

1. 精确台词、时长和段内 Shot 结构已锁定；
2. 所需人物图、说话人音色、干净首帧/已验收续接帧、人数匹配场景图和道具图已绑定；
3. Mixed 编号连续、职责唯一，规划图未进入；
4. 动作与运镜复杂度在段长预算内；
5. 起止状态、轴线、功能朝向、道具和下一段承接已核对；
6. 代码块无绝对时间码、裸素材 ID、旧式引用和非法画内文字；
7. 全剧七遍提示词二审与确定性 Markdown 校验均通过；
8. 同步画布后，实时有序输入边、音频、模型和素材合规状态的只读审计为零错误
   （`params` 为扁平 `prompt/ratio/resolution/duration`，无嵌套 `settings`）。
