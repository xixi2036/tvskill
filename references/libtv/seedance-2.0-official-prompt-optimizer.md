# Seedance 2.0 官方提示词优化适配

本文件吸收用户于 2026-07-23 提供的 `sd2-pe` 官方优化规则。Markdown 兼容层继续使用
`@[语义资产] {{Mixed N}}` 内部 DSL；同步到 TVMao 时确定性编译为带真实节点 ID 的
canonical mention，网页提交时再序列化为 `图片N/视频N/音频N`。官方能力、限制与故障处理事实见
[官方指南知识快照](seedance-2.0-official-guide-snapshot.md)。若与旧《三合一提示词》实例
冲突，模型代码块以本文件为准；旧实例中的场次、时长和逐镜秒数只保留在 Markdown
人工规划层。

## 1. 模型理解方式

Seedance 2.0 把输入理解为空间层和时间层：

- 空间层：主体身份、场景、位置、光线、道具和构图；
- 时间层：动作、表情变化、镜头运动、镜头顺序和声音。

提示词必须是工程指令，不是形容词堆砌。生成前检查八项：

1. 精准主体；
2. 动作细节；
3. 场景环境；
4. 光影色调；
5. 镜头运镜；
6. 视觉风格；
7. 画质；
8. 约束条件。

真人短剧还必须通过 [真人表演、眼神与对白合同](performance-dialogue-contract.md)：
把角色目标和潜台词转换为可见动作，明确眼神对象，给同步对白设置开口触发、
零或一个必要声音控制和说完后的活状态，并为多人镜头分配动作层级。

## 2. TVMao 引用适配

TVSkill Markdown 兼容层写成：

```text
@[单知影] {{Mixed 1}}
@[单知影音色] {{Mixed 2}}
@[首帧-3-1-A] {{Mixed 3}}
@[场景状态-Z班-占座] {{Mixed 4}}
```

TVMao 画布存储为：

```text
@[图片:n-character]（单知影）
@[音频:n-voice]（单知影音色）
@[图片:n-first-frame]（首帧-3-1-A）
@[图片:n-scene]（场景状态-Z班-占座）
```

网页提交模型前按实时有序入边序列化为 `图片1/音频1/图片2/图片3`。图片、视频、音频
各自从 1 编号；Mixed 仍按表格总顺序编号，两套编号不能直接等同。普通 `@图片1` 文本
不会在画布编辑器形成关联 chip。

复杂多主体时必须先定义，再用稳定标签：

```text
将 @[单知影] {{Mixed 1}} 中黑色低马尾、深蓝制服、冷静少女定义为 <主体1>；
将 @[李威] {{Mixed 2}} 中短黑发、深蓝制服、结实青年定义为 <主体2>；
将 @[场景状态-Z班-占座] {{Mixed 4}} 中当前人数的教室定义为 <场景1>。
```

规则：

- 官方允许使用 `主体1`、角色真名或“警察/小偷”等语义身份作为稳定标签；TVSkill 为便于确定性校验，默认统一使用 `<主体N>`，但这不是 Seedance API 的必填字段；
- 不同可识别人物必须使用不同的独立人物图片和不同 Mixed；
- 人物身份图不得与首帧、场景状态图、道具图共用 Mixed；
- 位置图、轨迹图、构图图、色块、假人、箭头和文字标注图只用于内部规划，严禁进入 Mixed；
- Mixed 中的空间锚只允许干净首帧、已验收续接帧和人数匹配的场景状态图；
- 同一人物可用大头照和全身照两张独立图，但禁止三视图、九宫格或多人拼图；
- 重要对白可增加同一人物的独立三分之四侧脸近照；近照使用自然肩颈和离镜视线，
  避免只用正面立正、直视镜头的证件式参考；
- 人脸参考优先放在素材顺序前部；
- 动作句中使用 `<主体N>`，不要让 `@[语义资产] {{Mixed N}}` 裸接动词或方位词；
- 禁止裸素材 ID。

## 3. 任务分类与复杂度路径

先判定任务类型，再决定提示词结构：

| 类型 | 官方语义 | TVMao 适配 |
|---|---|---|
| 多模态参考 | 参考图片、视频或音频生成新内容 | 用有序 input edge、node-id mention 与运行时 `图片N/视频N/音频N` 定义职责 |
| 编辑视频 | 在原视频上增加、删除或修改元素 | 必须直接写“严格编辑视频素材”，不能写“参考视频素材” |
| 延长视频 | 向前或向后续写原视频 | 必须直接写“向前/向后延长视频素材” |
| 组合任务 | 参考一个素材，编辑另一个视频 | 分清参考素材与被编辑视频的职责 |

编辑、延长和组合任务只有在 TVMao 当前模型 schema 确实暴露相应能力时才能使用；否则
不得把普通全能参考伪装成编辑或延长。

多模态参考再从两个轴判断复杂度：

- **时间维度**：单一连续动作/一句台词/一次状态展示为“少”；多事件链、状态递进、
  对话往返为“多”；
- **空间维度**：单场景固定机位为“少”；换场景、换机位、穿越多个区域为“多”。

只有两个维度都“少”才走路径 A。任一维度为“多”就走路径 B。素材数量、总秒数和
用户是否写了镜号只能作为辅助信号，不能代替时间/空间判断。特别禁止因为节点只有
5–8 秒就自动判成单镜，也禁止为了形式上的连续性把本应在同一事件链完成的动作拆成
多个相互独立生成节点。

### 路径 A：简单视频

单镜、单一连续动作，以及能力已确认的编辑、延长和组合任务，写成一段：

```text
任务句式，主体与素材绑定，场景与动作，风格与约束包。
```

### 路径 B：复杂影视化场景

多事件、多机位、多区域或长剧情使用三段论：

1. 总体设定 + 主体/场景/位置/音色定义；
2. 按事件顺序编排 `Shot N:`，每镜写唯一主运镜、动作表情、空间变化和声音；
3. 风格 + 画质 + 稳定 + 文字污染 + 多人防复制约束。

同一时空、同一人物关系下的多事件链，优先在一个路径 B 节点内部完成，减少独立生成
导致的人物瞬移、座位漂移和道具重置。原生音频同步对白可以进入多镜节点，但每个
`Shot N:` 仍只允许一位说话人和一个自然意群，并绑定该人物独立音色。

## 4. 分镜语法

TVSkill 最终提示词使用下面两种互斥语法：

```text
单一连续镜头，无剪切。景别，唯一主运镜。主体动作与表情；位置和空间变化；声音。

Shot 1:（分镜功能）景别，唯一主运镜。主体动作与表情；位置和空间变化；声音。
Shot 2:（分镜功能）景别，唯一主运镜。主体动作与表情；位置和空间变化；声音。
```

- 第一种连续单镜语法只用于具有明确不中断表演价值的单一事件；10 秒以上必须补`长镜头叙事意图：...`。其余多事件链默认使用第二种多镜语法；
- 只有确需片内剪切时才使用行首精确 `Shot N:`，编号从 1 连续递增；
- 禁止旧 `镜头N：`，也不得把连续单镜声明与 `Shot N:` 混用；
- 镜数由时间/空间事件密度决定，并用段长校准：10–13 秒建议 3–5 个、14–15 秒默认
  4–6 个清楚 `Shot N:`，每镜通常 2–4 秒并具备独立叙事功能；
- 不在模型提示词里写 `00:00.00–00:03.00`、`第5秒`等绝对时间；
- 单镜只指定一种主运镜；
- 动作用肢体部位、幅度、速度、力度和动作落点描述；
- 优先低缓连续动作，避免无必要的高爆发动作；
- 用肩颈、视线、手指、呼吸和步伐外化情绪；
- 同步对白按“开口触发 → 具体眼神对象 → 零或一个身体变化 → `{精确台词}` →
  零或一个声音控制 → 活状态”编译；
- 原生音频同步对白每个 Shot 一位说话人一个自然意群；同一 Shot 不混入 OS/VO、走位、递物、高速道具、群体反应、特效或精确文字；
- 六字以内短句一口自然说完，禁止放慢、停半拍、一字一顿和拖长；
- 剧本写“不看任何人”时给出正向目标，例如“视线始终落在后排靠窗座位”；
- 多人镜头只设一个表演焦点，最多一名人物完成一次小反应，其余人物保持持续微动；
- 多人正面动态必须写强方位、固定轴线和防重复约束；
- 精确时长只设置在 TVMao 节点扁平参数和 Markdown 元数据中。

## 5. 跨片段连续策略

独立生成无法保证上一段的像素终态自动成为下一段的物理初态。按下面的优先级选择：

1. **单节点多镜**：同一时空的多事件链优先合并为一个路径 B 节点，用 `Shot N:` 在节点
   内切换机位；这是避免跨节点人物位移最直接的办法。
2. **视频延长**：单场长对话、情绪递进和单一路径移动，若 TVMao schema 暴露延长能力，
   使用上一段已验收视频作为被延长对象；提示词写“向后延长”，不能写“参考该视频”。
3. **受控独立剪辑**：剧情转折、追逐、特效、精确文字、风险动作或新场景才拆成独立
   节点。边界必须落在动作完成、反应、视线对象、物件或明显景别变化上，不能要求两个
   独立节点伪装成同一个运动中的无缝长镜头。

必须拆段时：

- 上段结束前完成台词、口型、主动作和主运镜，并给出稳定落幅；
- 记录实际 `observed_end`，不要继续使用计划终态；
- 下一段同时绑定 canonical 人物/场景/道具和上一段已验收的续接帧；若平台支持视频
  参考或延长，优先使用已验收视频而不是只靠尾帧；
- 下一段从稳定构图启动新动作；移动镜遵循“稳—动—稳”；
- 相邻独立片段优先用反应切、视线切、物件切、动作完成切或明显景别变化，避免两个
  近似构图硬拼；
- 续接帧只允许一跳，每两到三段重新锚定 canonical 资产。

## 6. 特殊字符

模型代码块中强制使用：

- 台词：`{精确原文}`；
- 音效：`<脚步声>`；
- 背景音乐：`（背景中播放……）`；
- 可见字幕/标题：`【文字】`。

零文字短剧只允许 `【阶段N…】`、`【声音设计】`、`【关键约束】` 三类结构标记（见完成提示词规范的“正式段结构六件套”），其余 `【】` 一律禁止。不得再使用 `【空间锚点】`、`光影色调：【】`、`音效：【】`，否则可能被模型理解为需要生成画面文字。

## 7. 精简约束

复杂短剧提示词末段只保留与本镜直接相关的状态：

- 媒介：需要时写“真人实拍”，并用具体机位、物理光源、动作和声音证明；
- 稳定：锁定当前最脆弱的一到两项，如人物身份、嘴型期间的头部方向或手中道具；
- 连续：身份、服装、人数、位置、光向和道具状态一致；
- 零文字：保持无字幕，避免生成任何文字或字幕；
- 污染控制：不要生成水印，不要生成 Logo；
- 多人：只有存在人物复制风险时，保留一句防身份重复约束。

分辨率由节点参数控制。不要把“高清、8K、细节丰富、电影质感、色彩自然、
光影柔和”当作必挂画质包；删除普通缺陷词堆叠，只保留当前镜头确有风险的一条约束。

## 8. 音频

- 音色素材使用独立 audio-input，Markdown 中仍占一行 Mixed；只参考音色，不继承原音频台词；
- 台词逐字放在 `{}` 中；
- 重要同步对白优先单说话人、固定或稳定机位；嘴型期间不转头，不做复杂手势；
- 有合法音色或台词音频时明确它只控制该说话人的音色、节奏或口型；
- 台词、OS、VO 或旁白缺少任一说话人的已审核独立音色时，节点阻塞；不得关闭声音或用盲合成绕过；
- 声音控制只选一个真正必要的重音、音量或尾音方向；默认自然说话；
- 小语种标注语种；
- 音效放在 `<>`；
- BGM 放在 `（）`，无BGM时写 `（全程无背景音乐）`；
- 不为发音方便擅自改写剧本台词。

## 9. 审查与交付分层

只有以下关键歧义必须停下来让用户确认：多人左右/首尾帧映射不明、编辑或延长任务被
写成参考任务、同镜显式运镜冲突、同一主体的静态特征互相矛盾。普通缺失按剧本和已有
资产自动补全，并在人工审查层披露，不把“优化问题”复制到模型输入框。

生成前逐项核对八大要素。前两项“主体、动作”必填；场景、光影、运镜、风格、画质和
约束按任务需要补充。多人场景必须检查独立身份、方位、轴线和重复人物风险。参考人物
超过四人时优先拆镜或分组；长图、九宫格、人物三视图不得作为单一人物身份资产。

Markdown 人工层可以包含：

- 场次、地点、总时长和段时长；
- Mixed 上传顺序；
- 内部节奏和衔接说明；
- 语音对账。

模型代码块只能包含：

- 主体与素材定义；
- 镜头顺序和动作；
- 风格与约束。

不得把分析、优化问题、内部时间账本或绝对秒数复制进模型输入框。
