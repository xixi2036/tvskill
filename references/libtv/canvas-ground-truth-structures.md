## 3.4 运行前门禁（本文件此前漏记，三次绕过流程的根源）

节点建好 ≠ 可以跑。`node run` 之前必须过这道闸，且**必须带 `--pre-run`**：

```bash
python3 scripts/audit_canvas_nodes.py --project <N> --node <ID> --pre-run \
  --asset "角色-X=<输入节点ID>" --asset "视频场景锚-Y=<输入节点ID>" ...
```

`--pre-run` 把三项从提示升为**硬错误**：

| 硬错误 | 拦的是什么 |
|---|---|
| 素材合规状态未全部 `active` | 平台侧审核未通过的素材（含写实真人脸拦截），跑了必失败 |
| 运行前门禁要求 `idle` | 已跑过或已失败的节点被重复运行 |
| 一次性视频预算已消耗 `runCount≥1` | 同节点／同提示词指纹重跑，违反一次性预算合同 |

**`--asset` 映射必须与同步时完全一致。** 不传映射时审计拿不到语义 label，
会把每条绑定都误报成「语义与实际素材不一致」——一片假错，且真错被淹没。

> 2026-09-04 实证：跳过 `--pre-run` 直接 run，素材合规态那条只以 WARNING 出现，
> 被无视后烧掉一次 456 积分的生成，节点永久进入 `failed`（按一次性预算不可原地重跑）。
