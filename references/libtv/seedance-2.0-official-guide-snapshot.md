## 1. 模型理解与任务分类

Seedance 2.0 原生联合生成音频与视频，并把输入拆成：

- 空间层：主体、场景、位置、道具、构图、光线；
- 时间层：动作、表情变化、运镜、镜头顺序、声音。

提示词使用工程指令，核心公式为：

```text
精准主体 + 动作细节 + 场景环境 + 光影色调 + 镜头运镜 + 视觉风格 + 画质 + 约束条件
```

官方把参考生视频任务分为四类：

| 任务 | 目的 | 官方句式 |
|---|---|---|
| 多模态参考 | 提取主体、动作、场景、风格、音效或音色，生成新视频 | `参考图片N中的主体N，生成……`；`参考视频N中的动作/运镜/风格/音效，生成……`；`参考音频N中的音色，生成……` |
| 编辑视频 | 在原视频上增加、删除或修改元素 | `严格编辑视频N，将原特征修改为新特征`；未提及内容默认保持不变 |
| 延长视频 | 向前或向后续写 | `向前/向后延长视频N，生成……` |
| 组合任务 | 参考一个素材，编辑另一个素材 | `参考图片/视频N的参考维度，严格编辑视频X，具体编辑内容` |

编辑和延长任务直接指代 `视频N`，不要写成“参考视频N”，否则可能被模型误判为参考生成。

多模态参考任务再按两个轴判断结构：

- 时间维度：单一连续动作/一次状态展示为简单；多事件链、状态递进和对话往返为复杂；
- 空间维度：单场景固定机位为简单；多场景、多机位和跨区域移动为复杂。

只有两个维度都简单才使用一段式单镜。任一维度复杂就使用总体设定、镜头顺序、风格约束
三段式。素材数量、分镜数量和总秒数只是辅助信号，不能单独决定简单或复杂。

## 2. 主体定义

主体可以是人物、道具或场景。图片或视频中存在多个候选对象时，必须明确目标对象。

### 2.1 官方推荐方式

```text
将图片/视频N中的[2–3 个稳定静态特征]定义为[稳定标签]
```

稳定特征优先使用服装、发型、外观和类别。标签既可以是 `主体1`，也可以是角色名或语义身份，例如“张红”“警察”“小偷”。

多个素材指向同一主体时统一绑定：

```text
将图片1中的[…]、图片2中的[…]定义为主体1
```

多个主体分别定义，后续每次出现都持续使用同一标签，不能省略或随意更换称呼。

### 2.2 简单场景

未提前定义时，每次提及主体都要同时绑定素材，例如：

```text
张三@图片1
```

不要让素材编号裸接动词或方位词，也不要直接使用 Asset ID 代替 `图片N/视频N`。模型不能仅凭底层 Asset ID 建立内容关联。

### 2.3 TVSkill 的确定性约束

官方允许语义角色名和 `主体N` 两种稳定标签。TVSkill 默认统一使用 `<主体N>`，便于 Markdown 校验与跨段映射；角色真名仍保留在 `@[角色名] {{Mixed N}}` 的语义资产名中。

每个可识别人物使用独立人物图。人物身份图、干净首帧/续接帧、干净单视图视频场景锚不得共用 Mixed；位置图和轨迹图只用于内部规划，不进入 Mixed。这是 TVSkill 为降低串脸与职责污染而采用的更严格生产规则。

项目实证覆盖：用户要求 16:9 三视图长期复用时，TVSkill 允许每名角色的一张三视图母板作为
身份 Mixed，但必须明确不继承白底、多分格、中性站姿和直视视线，并由 9:16 干净首帧控制
表演与空间。此处覆盖下文官方通用兜底中的“不使用三视图”，不允许多人拼图。

## 3. 复杂提示词结构

### 3.1 八项检查

生成前检查：

1. 主体是否精确；
2. 动作是否可执行；
3. 场景是否清楚；
4. 光影与色调是否统一；
5. 运镜是否明确；
6. 风格是否稳定；
7. 画质要求是否存在；
8. 约束是否针对当前风险。

### 3.2 镜头顺序

官方原始指南建议复杂场景按“镜头1 / 镜头2 / 镜头3”的事件顺序描述，并指出模型对 `0–3 秒` 等精确时间限制的支持不稳定。TVSkill 在最终交付面统一转写：连续单镜写“单一连续镜头，无剪切”；片内剪切使用行首精确 `Shot 1:` / `Shot 2:`，不直接输出旧中文镜头标签。

每镜按以下顺序组织：

1. 景别、运镜或切换方式；
2. 主体动作与表情；
3. 位置或空间变化；
4. 音频信息。

### 3.3 动作与运镜

- 动作细化到手、腿、头、肩背，并写幅度、速度或力度；
- 优先低缓、连续的小动作；
- 写清动作惯性和前后衔接；
- 用视线、呼吸、肩颈、手指和步伐外化情绪；
- 一镜尽量只指定一种主运镜，避免推、拉、摇、移同时叠加；
- 标准词优先，例如中景、特写、全景、缓慢推镜、平稳横移、固定镜头。

### 3.4 画质、风格与约束

官方画质示例：

```text
高清，细节丰富，电影质感，色彩自然，光影柔和
```

常用边界：

```text
保持无字幕，避免生成任何文字或字幕。
不要生成水印。
不要生成 Logo。
```

动漫或非写实任务必须显式锚定风格，例如 `2D 日漫风格`、`3D 国风漫画`，避免漂移到真人写实。

## 4. 多模态素材职责

素材通常承担四类角色：

1. 角色锚定：锁定外观；
2. 场景定调：锁定环境与风格；
3. 运镜参考：锁定镜头语言、动作或特效节奏；
4. 节奏氛围：用音频控制音色、情绪和声音质感。

官方推荐通常使用 4–5 个高相关素材：

```text
角色图 1–2 张（面部特写 + 全身）+ 场景图 1 张 + 运镜视频 1 段 + 音频 1 段
```

素材并非越多越好。过多素材会竞争优先级，造成风格冲突、主体模糊或偏离需求。需要精准参考的素材应靠前。

Seedance 2.0 支持：

- 商品或物体的多视角图片参考；
- 角色、场景、Logo、服装和多元素的多图参考；
- 分镜图和多宫格构图顺序参考；
- 视频动作、运镜和特效参考；
- 视频元素的增加、删除与修改；
- 向前或向后延长；
- 多段视频轨道补齐。

对真人角色，能力上的“支持多视角”不等于生产上的“建议三视图”。官方故障排查明确指出：人物三视图或多视图可能被识别成多个主体，加剧 ID 漂移和双胞胎问题。该官方通用兜底已被上文第 2 节“项目实证覆盖”覆盖：本项目保留每角色一张 `16:9` 三视图身份母板长期复用，绑定句只继承五官、发型、体型和服装并排除白底、多分格、中性站姿与直视镜头视线；**多人拼图仍然禁止**。只有该覆盖不适用（例如确有特写保真需求）时才派生独立脸部工作图。

## 5. 音频、台词与文字

特殊字符：

| 信息 | 符号 | 示例 |
|---|---|---|
| 背景音乐 | `（）` | `（背景中播放快节奏摇滚乐）` |
| 音效 | `<>` | `<远处传来狗叫声>` |
| 台词 | `{}` | `{你好，世界}` |
| 字幕或标题 | `【】` | `【第一章：启程】` |

小语种台词要标注语种。台词语言尽量统一，避免无必要的中英文混用。

模型支持广告语、字幕和气泡文字，可指定内容、时机、位置、出现方式、颜色和风格。常用字比生僻字和特殊符号更稳定。

TVSkill 默认是真人短剧零文字任务，因此代码块中只允许 `【阶段N…】`、`【声音设计】`、`【关键约束】` 三类结构标记，其余 `【】` 一律禁用；精确字幕和版式文字交给后期。

## 6. 生成策略

### 6.1 延长与分段

- 单场文戏、长对话、情绪递进和单一路径移动：优先视频延长，保持沉浸与连续；
- 剧情转折、追逐、打斗、蒙太奇和快速复杂动作：独立分段生成后剪辑；
- 实际制作可混用，例如用延长完成连续对话，再拼接空镜或转场。

### 6.2 轨道补齐

官方指南快照写明：最多输入 3 段视频，输入总时长不超过 15 秒；模型会自动截取必要的首尾衔接片段。该限制属于指南中的模型能力说明，TVMao 是否支持此入口必须读取实时 schema。

### 6.3 文字与字幕概率

“保持无字幕”等约束只能降低概率，不能保证 100% 消除字幕。官方还建议：素材中不需要的文字先清除；业务允许时横屏的字幕概率通常低于竖屏，再由后期裁切。但 TVSkill 默认交付 9:16，不能静默改成横屏。

## 6.4 ⚠️ 平台硬限制：写实真人脸部素材自动拦截

**这是提交期的服务端拦截，不是概率问题，也不是提示词能绕过的。**

来源：MOKE SkillHub `global/seedance` 的平台参数速查表
（`⚠️ 硬限制 | 写实真人脸部素材自动拦截`）与其 `references/compliance.md`
（`上传清晰真人照片作主体参考 | 风险高 | 平台自动拦截写实真人脸部素材`）。

2026-09-04 本地实证：把一张 `gpt-image-2.1` 生成的 **16:9 角色身份设定板**
绑进视频节点后提交，服务端直接返回

```
upstream 400 InputImageSensitiveContentDetected.PrivacyInformation
The request failed because the input image 'content[1]' may contain real person
```

节点随即进入 `failed`。**注意两件事**：

1. **图像模型不拦，视频模型才拦。** `gpt-image-2.1` 正常出图、节点 succeeded，
   问题在下游 Seedance 提交时才暴露——所以资产验收通过 ≠ 能进视频。
2. **代价是一次性的。** 按一次性视频预算合同，该节点已登记为拒绝态，
   必须换资产后另建新节点，不能原地重跑。

### 触发形状（实测）

出问题的是设定板**左侧约 30% 的白底大幅正面头肩肖像**——它在形状上等同一张证件照，
是整张板里最像"真人照片"的部分。三个全身视图反而风险低。

### 规避（按风险从低到高排列）

- **提高风格化程度**：明确写风格化 3D 的可见特征（眼型/五官比例/皮肤材质的非写实处理），
  不要只写「不是照片级仿真人数字人」这类否定句——否定句挡不住渲染器把脸做写实。
- **避免白底大幅正面头肩肖像**作为视频输入：身份可由全身三视图承担；
  确需脸部保真时，用带环境光影的剧照式近景，而不是证件照式白底正脸。
- **先小成本验证**：新角色资产第一次进视频前，用最短时长/最低分辨率的
  一次性试提交探路，避免直接烧正式段的一次性预算。

### ⚠️ 更正：闸是有的，是没跑

本条**平台限制的文字说明**此前 tvskill 确实没有，但**运行时门禁一直存在**：

```bash
python3 scripts/audit_canvas_nodes.py --project <N> --node <ID> --pre-run --asset ...
```

`--pre-run` 会把素材合规态从 warning 升成**硬错误**，本次事故里它能拦住：

```
ERROR: Seedance 运行前素材合规状态未全部 active：['角色-姜月初', ...]
```

实际经过是：普通模式跑审计时该项以 `WARNING: 素材合规状态尚未 active` 出现，
被无视后直接 `node run`，才烧掉一次生成并废掉节点。

**结论不是「tvskill 缺闸」，是「没走 tvskill 的入口」。** 与 SKILL.md 的立场一致：
能落成闸的规则一律落成闸，只能靠自觉的规则一律假定会被跳过——本次即为后者的实例。

## 7. 常见问题与官方处理建议

### 7.1 人物 ID 漂移

根因常见于人脸图混入全身、姿态、服装和复杂背景，以及人脸占比过小。

处理：

1. 额外准备干净、无表情、以头部为主的人脸特写；
2. 用大头照锁面部，全身照锁妆造；
3. 重要身份素材前置；
4. 官方通用建议不使用人物三视图或多视图拼图；本项目按上文“项目实证覆盖”保留每角色一张 16:9 三视图身份母板，仍禁止多人拼图。

### 7.2 双胞胎、人物重复

该问题无法通过提示词 100% 消除。降低概率的方法：

1. 清楚定义每个角色与其独立参考图；
2. 固定人物数量、方位与轴线；
3. 使用单人独立照片；
4. 精简提示词，不把完整剧本直接塞入一次生成；
5. 末尾添加：

```text
视频全程禁止出现外形、着装、配饰完全一致的人物，禁止生成同款分身、双胞胎效果，同一画面中仅保留单个对应人物，不出现人物重复复刻。
```

### 7.3 参考人物超过 4 人

人物超过 4 人时稳定性下降，可能多生、少生或重复。官方建议先按每组不超过 4 人分组生成图片，再用分组图片生成视频。TVSkill 更优先拆段或拆镜，减少单次生成的人物密度。

### 7.4 字幕、Logo 和水印

- 字幕：加入无字幕、无文字约束，先清理参考素材中的非必要文字；
- Logo：加入“不要生成 Logo”；
- 水印：加入“不要生成水印”。

### 7.5 风格漂移

显式写目标风格，并尽量先把参考图转换到目标风格，再用于视频生成。

### 7.6 延长衔接跳变

官方后期建议：前一段末尾删 6 帧，后一段开头删 1 帧，再检查所有拼接点。仍可能存在轻微跳变；可让上一段在转场切镜处结束，下一段从新场景建立。

### 7.7 多次延长画质劣化

延长次数越多，画质劣化会叠加，人物脸部尤其明显。官方缓解建议包括：

- 使用高清图片重新锚定；
- 控制续写次数；
- 必要时先把原视频转为纯白 3D 白模，再作为运动结构参考续写。

白模方法改变视觉流程，TVSkill 不自动采用，必须由用户确认。

### 7.8 特效不准确

复杂特效的运动逻辑仅靠文字可能失真。优先上传目标特效视频，并明确只参考特效形态、轨迹和节奏。

### 7.9 片尾噪音

含旁白的视频结尾可能出现咔哒声或截断杂音。可重新生成，或在剪辑软件中用音量包络线把末尾淡出到 0。

### 7.10 中文发音

多音字、生僻字和形近字可能读错。官方建议可用发音一致的常用同音字规避，但这会改变提示词文字。TVSkill 必须同时保留原台词真值，并在人工交付层披露发音替代，不能静默改写剧本。

### 7.11 音色偏差

除绑定参考音频外，补充音色特征，例如年龄感、厚薄、颗粒感、速度和情绪；台词语气与参考音频越接近，音色还原通常越稳定。

## 8. TVMao 适配边界

官方指南示例使用带 `@` 的媒体编号；当前 TVMao 网页的实际存储与提交分两层：

```text
画布存储：@[图片:<nodeId>]（语义资产名）
模型提交：图片1（语义资产名） / 视频1（语义资产名） / 音频1（语义资产名）
```

执行规则：

- 图片、视频、音频分别按实时有序入边中的同类素材从 1 编号；Markdown Mixed 只是兼容 DSL，写入时必须编译为 node-id mention；
- 人物、场景、位置、动作视频和音色音频各自只承担一个主职责；
- 节点 ID 只存在于画布 canonical token，网页提交前必须剥离；不得把节点 ID、Asset ID 或 URL 发给模型充当语义引用；
- 复杂短剧使用“总体设定与定义 → 事件镜头顺序 → 风格与约束”；最终交付按本 skill 的连续单镜或精确 `Shot N:` 语法输出；
- 精确时长放在节点参数和 Markdown，不放入模型提示词；
- 用户要求操作画布时，先读取 TVMao 实时模型 schema；
- 指南中存在但 TVMao 未暴露的编辑、延长、轨道补齐或文字模式，不得声称已经可用；

## 6.5 资产生图侧的第二道平台闸：内容策略拦截（2026-09-04 实证）

§6.4 记的是**视频**侧的真人脸拦截。资产**生图**侧还有一道独立的闸，此前无记录。

### 实证

《万妖图录传》EP01 的「虎妖尸体」道具母板首次提交即被拒：

```
upstream 400: content_policy_violation
"生成的图片可能违反了关于暴力内容的防护限制"
```

被拒的原句是把伤口按临床解剖口径写细了：

> 巨大贯穿破洞，**创缘皮肉外翻**、边缘毛发被**血浸成暗红结块**，洞内为暗黑色不见细节…
> 插入处有**暗红血迹自伤口向下流淌**并已半凝固

### 改写后通过（同一画面意图，措辞换口径）

| 被拒写法 | 通过写法 |
|---|---|
| 尸体／死态 | 奇幻生物造型资产、静止态、如同已停止活动的雕塑 |
| 贯穿破洞、创缘皮肉外翻 | 圆形大面积**毛皮缺失区域**，内为均匀**暗色凹陷**，不表现内部结构细节 |
| 血浸成暗红结块、血迹流淌 | **干涸已久的深赭色斑块**，边缘有龟裂质感，**不表现流动的液体** |
| （无） | 【禁止】…不表现流动液体、飞溅或内部解剖结构 |

### 规则

1. **写画面结果，不写解剖过程**：「暗色凹陷」可过，「皮肉外翻」不可过。
2. **写已干涸的痕迹，不写流动的液体**：「深赭色斑块」可过，「血迹流淌」不可过。
3. **给它一个资产身份**：开头写「奇幻生物造型资产」「用于三维动画分镜的道具锚定」，
   比直接写「一具尸体」通过率高。
4. **负向清单里显式排除**：`不表现流动液体、飞溅或内部解剖结构`。

> 参考成片里同一具虎妖有更强的视觉冲击，说明**画面本身不越界，越界的是提示词的措辞口径**。
> 被拒不等于该画面做不出来，先按上表换口径重写，不要降低画面目标。

**流程含义**：被拒节点按一次性预算已是拒绝态，须**改写提示词后另建节点**
（新指纹），不得原地重跑——这与 SKILL.md:412 的返工条款一致。
